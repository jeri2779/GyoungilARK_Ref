구현 방법 제안 시 **최소 3가지**를, 각각 제안 이유 / 핵심 구조와 변경 범위 / 장점 / 단점과 실패 위험 / 예상 검증 항목 / 일정 영향과 함께. 마지막에 추천 순위와 채택 기준.

- **검증 → 변경 → 후처리 → 확정.** 실패 시 부분 점유가 남지 않게.

### 2.4 인터페이스 무도입 (`04_인터페이스_무도입_원칙.md`)

## 3. 명명 규칙

### 3.1 케이싱 (`Map_네이밍_컨벤션.md` §1)

| 대상 | 규칙 |
|---|---|
| 클래스·구조체·메서드·프로퍼티·이벤트·상수·enum | `PascalCase` |
| public·인스펙터 노출 필드 | `camelCase` |
| **private 필드** | **`_camelCase`** ⭐ 가장 자주 어긋나던 것 |
| 지역변수·매개변수 | `camelCase` |

### 3.2 형태 (`02_명명규칙_및_금지문법.md`)
- 클래스 = 역할 명사구 / 메서드 = **동사 + 명시적 목적어**(목적어 없는 동사 금지)
- bool 반환 = `Is`/`Has`/`Can` + 대상. 동사 원형 금지(`IsDie` → `IsDead`)
- 이벤트 = 과거분사 또는 명확한 시점

### 3.3 금지어·금지 문법 (전부 즉시 중단 사유)
1. 약어·한 글자 변수. **예외는 `for`문의 `i`, `j`뿐** (`go`, `t`, `p`, `r`, `e` 전부 금지)
2. 이중 해석 명명 (`GetCover`의 `Cover` = 덮개? 덮다?)
3. 모호 명명 (`RemoveAt`, `ToCell`)
4. 삼항 연산자
5. 매직넘버
6. 의미 불명확한 불리언 인자 (`GetTiles(origin, range, true)`) — 기존은 동결, **신규 금지**
7. 동명이의 메서드
8. **`Rent`/대여 · `Mover`/이동 · 라우팅** (별도 확정 금지어)

### 3.4 파일 접두 체계 (`Map_네이밍_컨벤션.md` §7)
**핵심 구분선: 칸 하나를 다루면 `Tile*`, 보드 전체·여러 칸이면 `Map*`.**

| 계층 | 폴더 | 접두 |
|---|---|---|
| 파사드 + 런타임 서비스 | Core | `Map*` |
| 칸 하나의 데이터·규칙 | Core | `Tile*` |
| **순수 알고리즘 도구(무상태·맵 전용 아님)** | **Core/Static** | **서술형 유지** |

| 디버그·시각화 | Debug | `*View`/`*Debug` (Map 금지) |

## 4. 구조 규칙

### 4.1 3층 계층 (`03_계층_폴더_메서드배치_규칙.md`)
```
[1층] 경계(MonoBehaviour) — 위임과 순서 조율만. 계산·판정·상태 저장 금지
   ↓
[2층] 기능 모듈(일반 C# 클래스) — 자기 역할 하나만. 수평 호출 금지
   ↓
[3층] 데이터·말단 — 보관과 순수 계산만. 상위를 알면 안 됨
```
- **수평 호출 해소는 두 가지뿐**: ① 공유 데이터를 3층 Store가 소유하고 주입 ② 순서가 필요하면 경계가 조율
- **모듈이 다른 모듈을 생성자로 받는 설계 금지.** Store와 3층 말단만 주입받는다
- 조립 전용 클래스(CompositionRoot) 만들지 않는다 — 경계가 직접 조립

### 4.2 Unity 함정
- 모듈은 **인라인 초기화 또는 지연 생성**. `Awake`에서만 만들면 에디트 모드 `[ContextMenu]`가 깨진다
- `[SerializeField]`·`[Inject]` 값을 **생성자에서 복사 금지**(주입이 생성보다 늦음). 지연 접근한다
- 폴더 이동 시 `.cs`와 `.meta`를 **반드시 함께**(GUID 보존)

### 4.3 메서드
- 배치 순서: 공개 진입 → 그것이 부르는 private → 그 다음 private → 정리 → 독립 보조. **체인 A가 끝나기 전에 체인 B를 끼우지 않는다**
- 추출 기준(하나라도 해당하면 즉시 추출): 조건 검증과 상태 변경이 함께 / 객체 생성과 등록이 함께 / Unity 조회와 도메인 계산이 함께 / 실패 메시지와 실패 판정이 함께 / 반복문에서 세 가지 이상 상태 변경
- **순수 코드 100줄 이하**(빈 줄·중괄호·주석 제외). 80줄 넘으면 미리 감사, 100줄 넘는데 분리할 역할이 안 보이면 중단·보고

### 4.4 규칙 충돌 시 우선순위
1. **규칙 17(외부 현행 유지) > 규칙 2·6·13(명명·폴더)**
2. **규칙 1·15(단일 책임·추출) > 규칙 12(100줄)**
3. **규칙 16(이해 가능성) > 이론적 완전성**
4. **SRP는 위 전부의 최상위** — 다른 규칙과 충돌하면 SRP가 이긴다

### C-5. `Area*` 접두가 이미 다른 용도에 배정돼 있다 ★

### C-6. `Core/Static` 배치가 그 폴더의 정의와 어긋난다 ★
`Map_네이밍_컨벤션.md` §7.1: **Core/Static = "순수 알고리즘 도구(무상태), 맵 전용 아님(범용)"** — 그래서 `GridCalculator`·`Pathfinder`가 여기 있다.

그런데 신규 `AreaAnchor`는 `Tile`을, `AreaPlace`는 `MapBoard`·`Tile`·`OccupantKind`를 직접 받는다. **범용이 아니라 맵 전용이다.**
→ `AreaCalc`만 순수(좌표 계산)라 `Core/Static`에 맞고, 나머지 둘은 위치가 틀렸다.

**✅ 2026-08-15 확인 — 이미 옮겨져 있음**: 현재 실제 경로는 `AreaCalc.cs`·`AreaAnchor.cs` = `Assets/Script/Map/Place/Area/`, `AreaPlace.cs` = `Assets/Script/Map/Place/Board/`다. `Core/Static`에는 없다(`Core/Static`엔 `GridCalculator`·`TileLink`·`TileShapeQuery` 3개뿐, 디렉터리 listing으로 확인). 지적된 배치 위반은 해소됐다.

### C-7. 접두 체계로 보면 이름이 `Map*`이어야 한다
§7.1의 핵심 구분선은 **"칸 하나 = `Tile*`, 보드 전체·여러 칸 = `Map*`"** 다.
다중 점유는 정의상 **여러 칸**을 다룬다 → 규칙대로면 `Map*` 접두다.

**⬜ 2026-08-15 확인 — 논거가 사라졌다**: 이 지적의 근거는 "다중 점유는 여러 칸을 다루니 `Map*`이어야 한다"였다. 그런데 다중 칸 점유가 죽은 기능이 되면서 **이 세 클래스는 실제로 칸 하나만 다룬다.** 접두 체계(`칸 하나 = Tile*`)로 보면 오히려 `Map*`이 아니다. 이름 변경 근거가 없어졌으므로 현행 유지.
